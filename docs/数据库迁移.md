# 数据库迁移

后端启动前自动执行 `python -m finagent.migrate`（Alembic `upgrade head`）。新安装无需手动迁移；迁移失败会阻止 API 启动。同一数据库不要同时运行多个迁移进程。

- AgentScope 管理自己的迁移，版本表为 `public.alembic_version`。
- FinanceAgent 迁移位于 `backend/finagent/migrations/`，版本表为 `fin.alembic_version`。
- `db/init.sql` 仅在数据库卷首次初始化时创建 vector 扩展和 schema，应用表的后续变更由迁移完成。
- 不要修改数据库 search path 或操作 AgentScope 的版本表来绕过应用迁移。

## 查看版本

```bash
docker compose exec backend python -m finagent.migrate current
docker compose exec backend python -m finagent.migrate history
```

## 接管旧版 schema.sql 创建的数据库

如果已有 `fin` 表但没有应用迁移版本，启动会拒绝自动接管。**不要删除 `pgdata` 来解决这个问题。**

1. 构建新后端镜像，停止应用写入，制作可恢复的 PostgreSQL 备份。备份包含凭证，不要提交到 Git；可存放在已忽略的 `data/backups/`。
2. 在独立、可丢弃的 PostgreSQL 16/pgvector 数据库上升级到 `0001_baseline`，对比旧数据库的领域 schema，排除 `fin.alembic_version`。检查列、类型、默认值、可空性、全部约束、序列归属、索引、`NULLS NOT DISTINCT` 和 vector 维度/HNSW。仅比较表数量不够；`backend/tests/schema_snapshot.py` 提供只读元数据快照辅助函数。
3. **仅在 schema 匹配时**注册基线：

   ```bash
   docker compose run --rm --no-deps backend python -m finagent.migrate stamp-baseline --verified
   docker compose up -d --no-deps backend
   ```

   `--verified` 表示操作者确认已备份并完成比较，**不代表程序已自动验证 schema**。命令只检查基线表是否存在及是否尚未登记版本。如有差异，需另行处理，不要 stamp `head` 或强制接管。
4. 检查 `current`、`/fin/healthz`、原有行数和序列，以及框架版本未被修改。Stamp 不会重建领域表。

## 新增迁移

安装后端依赖后，在仓库根目录执行（Bash/WSL）：

```bash
PYTHONPATH=backend python -m finagent.migrate revision -m "describe the schema change"
```

使用带 schema 的 Alembic 操作或 SQL 编写生成文件中的 `upgrade()` / `downgrade()`。项目没有 ORM 模型或自动生成迁移；不要修改已应用的 revision。初始迁移是不可变快照，旧版 DDL 仅保留在 `backend/tests/fixtures/legacy_schema.sql` 作为测试基准。

重建并启动后端即可应用新迁移。先在独立测试数据库验证升级和可逆降级。禁止降级到 `0001_baseline` 之前，以免删除全部领域数据。修改 `docs/数据结构.md` 不会自动修改数据库。

## 迁移回归测试

集成测试只读取 `MIGRATION_TEST_ADMIN_URL`，不使用日常 `DATABASE_URL`。请指向独立、可丢弃的 PostgreSQL 16/pgvector 服务；测试角色需能创建/删除数据库和创建 vector 扩展。每个测试创建 UUID 命名的数据库并清理，不配置该变量时跳过相关测试。**不要指向开发或生产数据库。**

安装后端依赖后执行（Bash/WSL）：

```bash
export MIGRATION_TEST_ADMIN_URL='postgresql://TEST_USER:TEST_PASSWORD@TEST_HOST:5432/postgres'
PYTHONPATH=backend python -m unittest discover -s backend/tests -t backend -v
```

PowerShell 用法及新库/旧库升级、数据保留、回滚、框架版本隔离等覆盖范围见 `backend/tests/test_migrations.py`。
